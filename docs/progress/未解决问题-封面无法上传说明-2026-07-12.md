# 未解决阻塞：组局封面无法上传到腾讯 COS

## 状态

- 状态：阻塞（需要腾讯 COS 真实凭证）
- 发现时间：2026-07-12
- 影响范围：小程序“发起组局”页面上传必填封面，进而阻止组局发布
- 生产接口：`POST /api/app/files/upload-token`

## 已确认现象

小程序发布组局时提示 `invalid file request`。本次测试图片本身符合规则：

- 文件类型：`image/png`
- 文件大小：67,405 字节
- 允许类型：JPG/JPEG、PNG、WEBP
- 最大大小：10MB

因此该问题不是封面图片格式或大小不合规。

## 根因证据

生产日志与数据库复核确认存在两个连续问题：

1. 后台原先使用进程内 `nextID` 生成 `storage_key`。服务重启后计数器归零，可能与数据库已有记录冲突，日志错误为：
   `duplicate key value violates unique constraint "uk_files_storage_key"`。
2. 存储键冲突修复后，使用同一测试账号、同一 PNG 和同一接口参数复测，日志明确返回：
   `create upload target: cos signer not configured`。
3. 生产容器中 `COS_SECRET_ID` 和 `COS_SECRET_KEY` 去除空白后的长度均为 `0`。
4. 当前非敏感配置为：
   - `APP_ENV=staging`
   - `STORAGE_PROVIDER=cos`
   - `STORAGE_UPLOAD_BASE_URL=https://static.haowan.net.cn`
5. 项目示例配置指定的 COS 上传端点为：
   `https://haowan-prod-1317494733.cos.ap-nanjing.myqcloud.com`。

## 已完成修复

- 数据库模式下的文件存储键已改为随机唯一标识，不再依赖进程内计数器。
- 生产后台已部署该修复。
- 已增加安全诊断日志，仅记录用户 ID、业务类型、对象 ID、文件名、MIME、大小和错误类型，不记录任何密钥。
- 小程序封面区已明确展示格式和大小要求。
- 小程序已保留真实 `fileName`、`mimeType` 和 `size`，不再把文件大小错误上报为 1 字节。
- 已增加临时发布兜底：开关关闭时页面直接展示并提交系统默认封面，不请求 COS，不再阻断组局发布。
- 前端开关：`miniprogram-client/config/feature-flags.js` 中的 `gameCoverUploadEnabled`。当前为 `false`，直接使用默认封面；COS 配置并通过真实上传验证后改为 `true`。

## 当前阻塞条件

代码无法生成或推断腾讯云账号的真实密钥。需要由腾讯云账号管理员提供或在生产服务器安全配置：

- `COS_SECRET_ID`
- `COS_SECRET_KEY`
- 正确的 `STORAGE_UPLOAD_BASE_URL`（应核对为目标 COS Bucket 上传端点）

禁止将真实密钥提交到 Git、文档、聊天记录或前端代码。

## 解除阻塞后的操作

1. 将真实 COS 凭证写入生产服务器 `/opt/zhw-mini/deploy/env.prod`，只允许服务器管理员读取。
2. 核对上传端点、Bucket、地域和密钥权限，权限至少覆盖指定前缀的对象上传。
3. 重建并重启 `go-api`。
4. 调用上传凭证接口，确认返回成功且包含 COS 表单签名。
5. 使用真实 PNG 完成 COS multipart/form-data 上传，确认 HTTP 200/204。
6. 创建组局并确认 `coverFileId`、局封面下载地址及首页卡片封面均正常。
7. 检查容器健康、重启次数和错误日志。

## 完成标准

- 同一封面连续上传不发生 `storage_key` 冲突。
- 上传凭证接口不再返回 `invalid file request` 或 `cos signer not configured`。
- COS 实际上传成功。
- 创建组局成功，详情页和局卡片显示后台封面。
