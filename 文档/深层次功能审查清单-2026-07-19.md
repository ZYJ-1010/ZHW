## 3. 功能流程清单与问题

### F01 邀请进入、注册和登录

**要求流程**：邀请海报/二维码/链接进入 -> 后端校验邀请码 -> 区分注册或登录 -> 微信登录 -> 建立永久邀请关系 -> 进入实名或首页。

**当前实现**：`auth.Service`、`/api/app/invites/precheck`、`/api/app/invites/entries`、微信登录和后台邀请关系管理均已存在。

**不符合项**：

- 生产 `PROD` API 仍使用 `https://api.example.com` 占位地址，真实小程序无法完成主链路。
- `docs/需求细节`要求无邀请码不能进入核心注册流程，但近期清单又允许无邀请码进入登录页手动输入，文档口径冲突，需要甲方确认唯一规则。
- 微信 `code2Session`、URL Link、小程序码、邀请海报仍未完成真实生产联调。

**等级**：P0 / 外部阻塞。

### F02 实名、手机号和人工审核

**要求流程**：用户提交手机号/实名资料 -> 格式校验 -> 后台人工审核 -> 通过或驳回并填写原因 -> 用户看到状态 -> 驳回后重新提交。

**当前实现**：身份证和手机号格式校验、实名记录、人工审核、驳回原因、通知和脱敏字段已存在。

**不符合项**：

- 当前登录换正式 token 的条件是 `identity.IsVerified`，普通玩家也会被要求完成强实名；文档明确“玩家不强制实名”，两者冲突。
- 后台实名列表和详情默认只返回脱敏字段；文档要求新提交记录在有权限时可查看完整身份证号和手机号，旧记录无法还原时才脱敏，当前权限分级和完整字段展示尚未闭环。
- 短信、FaceID、真实微信手机号授权没有完成生产联调。

**等级**：P0。

### F03 行家/领路人申请入口与审核

**要求流程**：用户进入角色入口 -> 先看条件页 -> 下一步进入资料页 -> 上传资质/计划书 -> 提交 -> 后台审核 -> 通过授予角色，驳回可重提。

**当前实现**：角色配置接口、申请接口、审核接口、角色授予、审核通知和页面流转已存在。

**不符合项**：

- 前端仍保留大量 `DEFAULT_EXPERT_APPLY_CONFIG`、`DEFAULT_GUIDE_APPLY_REQUIREMENTS` 兜底；接口异常时可能展示与后台规则不一致的条件。
- 后台白名单/导入授予能力已有入口，但尚未形成批量导入、模板下载、结果回执和审计验收闭环。
- 行家申请计划书、资质文件和企业认证资料的字段仍有页面模型与后端模型不完全一致的问题。

**等级**：P1。

### F04 角色申请条件与会员口径

**要求流程**：实名认证、企业认证/资质、发起/参与次数、信用分、计划书全部校验；会员等级条件一期关闭；满足条件后进入人工审核。

**当前实现**：角色条件已读取后台运营规则；会员等级与成长等级已拆分，会员条件默认关闭。

**不符合项**：

- 条件规则同时存在 `role` 配置、`guide_qualification_rules` 和 `operation.rules` 三套来源，存在后台修改一处、前端展示另一处的风险。
- 企业认证、实名和资质认证状态的最终生效条件没有统一成一个后端资格快照。
- 领路人“条件 + 付费”双门槛仍有占位订单逻辑，不是真实支付状态。

**等级**：P1 / 一期支付边界需明确。

### F05 创建组局

**要求流程**：填写标题/主题/介绍/类型/地点/人数 -> 校验 5-8 人和每日上限 -> 保存草稿或提交审核 -> 待审核局不可公开。

**当前实现**：创建接口、草稿、地图选点、人数和每日上限、审核状态、状态日志均有实现。

**不符合项**：

- 小程序创建局只允许免费局，后台可创建全部类型；文档已明确，但前后台类型配置仍存在多套枚举，需做最终四种一级类型口径确认。
- `games.Service` 仍使用固定常量进行底层校验，后台运营规则是在 App API 层补校验；后台或其他内部调用可能绕过同一规则。
- 创建地点、地址、经纬度的真实地图服务和真机回填仍未验收。

**等级**：P1。

### F06 局审核、驳回与重新提交

**要求流程**：提交 -> 待审核 -> 后台勾选审核 -> 通过进入招募 -> 驳回必须填写原因 -> 用户查看原因并修改重提。

**当前实现**：后台列表、详情、批量勾选审核、驳回原因、状态日志和用户端展示已存在。

**不符合项**：

- 后台批量审核、驳回、重提的浏览器 E2E 证据缺失。
- 组局审核、入局审核、角色审核的驳回原因字段命名不统一，前端有 `reason/rejectReason/reviewRemark` 多种兼容写法。
- 后台待处理红点和跨模块待办计数尚未形成统一数据源。

**等级**：P1。

### F07 首页、局列表、状态和排序

**要求流程**：只返回审核通过且可报名的局 -> 过滤已取消/已结束/报名截止 -> 卡片展示真实类型和状态 -> 排序独立生效。

**当前实现**：`publicGames`、状态 DTO、列表接口、卡片状态动作和基础排序已实现。

**不符合项**：

- 仍需验证所有状态组合：报名未开始、报名已截止、已满、进行中、待确认、已完成、已取消、争议中是否全部从“可加入”列表过滤。
- 分享页、成功页、审核详情页仍有真实接口失败时显示默认示例数据的路径，不能作为真实业务展示。
- 排序、局类型和状态字段在前端多个页面存在兼容别名，需做一次字段契约收口。

**等级**：P1。

### F08 入局申请、满员和并发审核

**要求流程**：用户申请 -> 校验报名窗口/实名/局条件/重复申请/容量 -> 待审核 -> 发起人或主行家审核 -> 满员后拒绝新增申请。

**当前实现**：申请、取消、审核、窗口、重复申请和数据库容量保护已存在。

**不符合项**：

- P1-11 尚未完成：成员退出、人数计数和信用扣分流水不是同一个事务。
- 申请被拒绝时，后台和小程序通知链路存在多种状态/理由字段，需做完整异常流验收。
- 并发锁主要覆盖审核容量，邀请接受、退出、重申请和自动入局仍需多实例压测。

**等级**：P1。

### F09 成团、手动开始和锁定

**要求流程**：通过成员达到 5 人 -> 成团/创建唯一 IM -> 组局人或主行家手动开始 -> 开始后锁定申请/邀请/审核。

**当前实现**：状态机、`full`、`in_progress`、开始原因、操作者、时间和唯一房间回调已存在。

**不符合项**：

- 状态机已统一，但操作超时和自动流转规则只是配置存储，未完整接入定时任务。
- 成团自动开始与手动开始的产品口径在文档中同时出现，需要确认一期最终行为。
- IM 创建失败重试、状态恢复和后台红点需要真实运行环境验证。

**等级**：P1。

### F10 局内 IM、文件和语音

**要求流程**：成员进入唯一房间 -> 文字/图片/文件/语音发送 -> 敏感词拦截 -> 非成员不可查看/下载 -> 局结束后只读或归档 -> 争议时后台保留。

**当前实现**：WebSocket、HTTP 消息、图片/文件/语音文件、文件归属校验、敏感词、归档和后台消息证据均有实现；私聊语音仍被禁止。

**不符合项**：

- 文档早期写“文件可预留”，用户后续明确要求语音和文件；代码已支持，但 OpenAPI 和小程序真实上传/播放/下载仍需补齐验收。
- 真实 WebSocket/对象存储/OpenIM 运行环境未完成联调。
- `go test ./internal/appapi` 的 WebSocket 测试在当前受限环境无法监听端口，不能替代真实验收。

**等级**：P1 / 外部阻塞。

### F11 行家进度反馈与协作

**要求流程**：进行中 -> 行家定期提交进度和说明 -> 每日提醒 -> 用户端和后台展示当前及历史进度。

**当前实现**：反馈、历史、提醒接口和详情页存在。

**不符合项**：

- 定时提醒任务是否在生产调度器实际运行没有证据。
- 主行家、协同行家、领路人查看范围和提交权限需要逐角色验收。
- 空进度页、状态不匹配和取消后进度残留仍需回归。

**等级**：P1。

### F12 服务确认、评价和再玩一局

**要求流程**：行家提交完成 -> 成员确认 -> 评价提醒 -> 多方互评 -> 记录再玩意向 -> 生成经验/信用/积分/成就。

**当前实现**：确认、评价待办、评价提交、防重复、意向、成长和低分信用联动已存在。

**不符合项**：

- P1-07 分润状态仍只有 `pending_settlement/frozen/settled` 主链路，缺少支付中、失败、退款、回退、争议等完整状态。
- 评价完成后的“再玩一局”三选项和同局好友邀请流程需真机验证不可返回、邀请而非复用旧成员数据。
- 评价提醒定时任务和通知模板没有完整生产发送证据。

**等级**：P1。

### F13 成长、信用、积分、成就和足迹

**要求流程**：行为事件 -> 写经验/积分/信用流水 -> 计算等级 -> 个人中心展示 -> 后台可追溯来源。

**当前实现**：成长规则、积分规则、信用扣分规则、成就配置和积分过期统计已接后台。

**不符合项**：

- 任务奖励已经能配置展示，但任务完成奖励流水、领取状态和重复奖励规则还没有形成完整运营任务系统。
- 成就“不同角色配置”后台入口和角色化发放规则仍需确认。
- 积分过期目前是查询统计，不是完整的过期扣减、流水、通知和定时任务。

**等级**：P1。

### F14 分润、订单、结算和分账

**要求流程**：服务完成 -> 评价完成 -> 无争议 -> 生成分润 -> 待结算 -> 结算/对账；异常进入冻结、退款、回退或失败重试。

**当前实现**：模板、比例、试算、收益账户、流水、冻结和线下结算占位已存在；真实支付不属于一期正式功能。

**不符合项**：

- P1-07 明确未完成：支付、退款、争议、失败、回退状态和迁移不完整。
- 资金服务是 Java HTTP 占位实现，不是持久化资金服务，不能视为真实分账。
- 争议冻结、结算登记、收入账户和分润记录的事务一致性、对账和重试尚未完成。

**等级**：P0/P1（一期占位可接受，正式分账不可宣称完成）。

### F15 举报、申诉、敏感词和通知

**要求流程**：用户提交举报/申诉和证据 -> 后台分配/处理 -> 冻结相关收益和留存 IM -> 通知用户 -> 可申诉或撤回。

**当前实现**：举报、申诉、证据归属、后台处理、分配、通知、敏感词和风险日志均有实现。

**不符合项**：

- 举报中心、系统通知、消息中心的真实数据与空态仍需真机验收，不能只看 API 返回。
- 订阅消息模板和实际发送依赖微信生产配置。
- 举报处理后冻结分润、保留 IM、申诉通过恢复信用/收益的事务边界需要专项验收。

**等级**：P1 / 外部阻塞。

### F16 个人中心、资产、订单和系统管理

**要求流程**：个人资料 -> 实名/角色/会员 -> 我的局/申请/邀请 -> 收益/积分/订单 -> 协议/反馈/屏蔽/申诉。

**当前实现**：大部分页面和接口已存在，资产、积分商城、兑换订单、反馈、协议、头像、技能等已接口化。

**不符合项**：

- 个人中心系统管理页的 `personalInfo/enterpriseInfo/certifications/skillSlots` 与后端模型仍存在字段语义不一致。
- 积分订单物流、详情、取消的完整履约状态仍不完整。
- 多个成功页、分享页、系统管理页仍有前端默认示例数据，接口失败时可能显示非真实内容。

**等级**：P1。

### F17 领路人邀请网络和人脉关系

**要求流程**：领路人入口 -> 邀请人列表 -> 被邀请人组局记录 -> 关系网络 -> 邀请/收益/排行。

**当前实现**：邀请概览、记录、排行、收益、成员详情、连接关系接口和页面存在。

**不符合项**：

- 首页动态地球/关系网所需节点、边、在线、热力和布局摘要字段不完整。
- 邀请关系修改、收益计算和关系网络统计需在后台权限和日志矩阵下验收。

**等级**：P1。

### F18 LBS、地图和二期边界

**要求流程**：授权定位/手动位置 -> 创建局保存地点 -> 附近局和距离 -> 同城筛选；复杂城市玩法属于二期/三期。

**当前实现**：基础地图、定位、附近局、距离、城市码和地图入口已存在；复杂地图页面通过子包保留但未作为一期入口。

**不符合项**：

- 真实地图 Key、域名和真机定位精度未验收。
- 地图半径后台配置与环境配置存在两套来源，需统一优先级。

**等级**：P1 / 二期边界问题。

### F19 PC 后台、RBAC 和操作日志

**当前实现**：后台登录、权限码、角色、操作日志、快照字段和多个业务模块均有实现。

- 真实权限矩阵和浏览器 E2E 未完成，不能只以默认角色 seed 判定通过。

- 固定格式导出、导出下载权限、敏感字段展示权限和操作日志完整查看权限需逐角色验收。

### F20 数据看板、行为、导出和 AI 数据基础

### F22 OpenAPI、前端路由和自动检查

**要求流程**：前端 API -> Go 路由 -> OpenAPI -> 测试用例三方一致；新增接口必须同步。

**当前结果**：

- 小程序 API 静态检查发现 6 个地图二期接口差集。
- OpenAPI 静态检查发现 7 个新增路由缺失。
- 页面流脚本对小程序子包页面存在误报，当前脚本没有解析 `subPackages`，检查结果不能直接作为真实页面 404 结论。

**等级**：P1；脚本本身也需要修正。

### F23 前端业务兜底与 Mock 数据

**要求流程**：真实接口成功 -> 展示真实数据；接口失败 -> 空态/错误态；不能展示假用户、假订单、假金额或假局。

**当前实现**：大量业务默认值已迁移到后端配置或 mock seed，但仍保留多处 `DEFAULT_*` 和 `FALLBACK_*`。

**不符合项**：

- `game/share`、`success-guide`、`success-expert`、`role/flow`、`map/index` 等页面仍有可能在接口失败时显示默认业务内容。
- `api/mock.js` 保留大量示例用户、订单、局和文案；需要明确只能在本地开发模式启用，不能进入体验版/正式版。
- 小程序 Mock 与 Go API 的字段和默认值没有自动契约校验。

**等级**：P1。

### F24 一期、二期、三期边界

**要求流程**：一期只交付邀请、实名、角色、组局、审核、入局、IM、确认、评价、成长、基础分润、举报和后台；AI/复杂地图为二期，元宇宙为三期。

**当前结论**：边界总体已在文档中明确。

**不符合项**：

- 部分前端路由和 API 仍保留复杂地图、城市玩法和推荐占位，容易被误判为一期已完成。
- 真实支付/退款/分账属于二期，但当前收益和资金占位接口需要在验收材料中明确标注“占位”，不能写成正式支付完成。
- 原始文档中 IM 文件是否一期必须项与后续甲方要求存在冲突；按最新要求以文字、图片、语音、文件为准，私聊语音仍保持关闭。

**等级**：P1 / 口径管理。
