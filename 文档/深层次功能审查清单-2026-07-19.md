## 2. 甲方最新确认口径

以下口径覆盖早期文档中的冲突描述，后续验收以本节为准：

1. 邀请入口：因微信平台限制，允许先进入登录页手动输入邀请码；URL Link 需要正式上线后才可用。
2. 实名认证：普通玩家不要求强实名；只有行家和领路人申请/使用对应身份时要求实名认证。
3. 会员等级：一期没有支付和会员购买，行家、领路人申请不校验会员等级。
4. 身份授予：后台可以按用户 ID 直接授予行家或领路人身份，作为一期白名单/运营开通方式。
5. IM：一期暂时使用本地轮询；OpenIM 接入属于二期，不作为一期缺陷。
6. 支付和分润：一期不启用支付、会员购买和真实分润，只保留接口、模板、状态和数据结构。

## 4. 功能流程清单与问题

### F01 邀请进入、注册和登录

**要求流程**：邀请海报/二维码/链接进入 -> 后端校验邀请码 -> 区分注册或登录 -> 微信登录 -> 建立永久邀请关系 -> 进入实名或首页。

**当前实现**：`auth.Service`、`/api/app/invites/precheck`、`/api/app/invites/entries`、微信登录和后台邀请关系管理均已存在。

**当前口径**：

- 因微信平台审核/入口要求，用户可先进入登录页手动输入邀请码；这不是业务绕过，后端仍必须校验邀请码。
- 小程序尚未正式上线前不能使用 URL Link，属于上线前置条件，不作为当前代码缺陷。
- 当前小程序生产 API 已配置为 `https://api.haowan.net.cn`，IM 地址为 `wss://im.haowan.net.cn`；域名部署项按已完成处理，后续只需继续做线上回归。

**等级**：上线前置条件。

### F02 实名、手机号和人工审核

**要求流程**：用户提交手机号/实名资料 -> 格式校验 -> 后台人工审核 -> 通过或驳回并填写原因 -> 用户看到状态 -> 驳回后重新提交。

**当前实现**：身份证和手机号格式校验、实名记录、人工审核、驳回原因、通知和脱敏字段已存在。

**不符合项**：

- 普通玩家不再被强制实名；只有行家/领路人身份用户需要实名，代码已按此口径处理。
- 后台审核列表和详情已能显示脱敏手机号、姓名和身份证号；可解密的新记录同时提供完整字段，旧记录无法还原时保留脱敏展示。
- 当前仅腾讯云短信真实发送 Key/审核仍未完成；在审核通过前继续使用一期固定验证码方案。

**等级**：已闭环；短信属于外部前置条件。

### F03 行家/领路人申请入口与审核

**要求流程**：用户进入角色入口 -> 先看条件页 -> 下一步进入资料页 -> 上传资质/计划书 -> 提交 -> 后台审核 -> 通过授予角色，驳回可重提。

**当前实现**：角色配置接口、申请接口、审核接口、角色授予、审核通知和页面流转已存在。

**当前口径**：

- 一期关闭会员等级条件，行家/领路人不要求购买会员。
- 后台可以按用户 ID 直接授予行家或领路人身份，该路径是一期有效运营方式。

**仍需整改**：

- 前端仍保留大量 `DEFAULT_EXPERT_APPLY_CONFIG`、`DEFAULT_GUIDE_APPLY_REQUIREMENTS` 兜底；接口异常时可能展示与后台规则不一致的条件。
- 白名单/导入授予需要补批量导入、结果回执和审计验收。
- 行家计划书、领路人计划书、企业认证资料字段仍需与后端申请模型统一。

**等级**：P1。

### F04 角色申请条件与会员口径

**要求流程**：实名认证、企业认证/资质、发起/参与次数、信用分、计划书全部校验；会员等级条件一期关闭；满足条件后进入人工审核。

**当前实现**：角色条件已读取后台运营规则；会员等级与成长等级已拆分，会员条件默认关闭。

**当前口径**：

- 会员等级条件一期关闭。
- 普通用户满足实名认证、企业/资质、发起/参与次数、信用分和计划书条件后，提交后台人工审核。
- 后台可以直接按 ID 授予行家/领路人身份。

**仍需整改**：

- 申请展示和提交校验已统一读取 `operation.rules`，后台人工白名单仍作为明确的运营开通通道。
- 申请提交时已落库实名、企业认证、次数、信用分和计划书条件快照；仍需补后台快照展示字段和历史数据迁移验收。

**等级**：P1。

### F05 创建组局

**要求流程**：填写标题/主题/介绍/类型/地点/人数 -> 校验 5-8 人和每日上限 -> 保存草稿或提交审核 -> 待审核局不可公开。

**当前实现**：创建接口、草稿、地图选点、人数和每日上限、审核状态、状态日志均有实现。

**不符合项**：

- `games.Service` 仍使用固定常量进行底层校验，后台运营规则是在 App API 层补校验；后台或其他内部调用可能绕过同一规则。
- 创建地点、地址、经纬度的真实地图服务和真机回填仍未验收。

**等级**：P1。

### F06 局审核、驳回与重新提交

**要求流程**：提交 -> 待审核 -> 后台勾选审核 -> 通过进入招募 -> 驳回必须填写原因 -> 用户查看原因并修改重提。

**不符合项**：

**等级**：P1。

### F07 首页、局列表、状态和排序

**要求流程**：只返回审核通过且可报名的局 -> 过滤已取消/已结束/报名截止 -> 卡片展示真实类型和状态 -> 排序独立生效。

**当前实现**：`publicGames`、状态 DTO、列表接口、卡片状态动作和基础排序已实现。

**不符合项**：

- 排序、局类型和状态字段在前端多个页面存在兼容别名，需做一次字段契约收口。

**等级**：P1。

### F08 入局申请、满员和并发审核

**要求流程**：用户申请 -> 校验报名窗口/实名/局条件/重复申请/容量 -> 待审核 -> 发起人或主行家审核 -> 满员后拒绝新增申请。

**当前实现**：申请、取消、审核、窗口、重复申请和数据库容量保护已存在。

**等级**：P1。

**要求流程**：授权定位/手动位置 -> 创建局保存地点 -> 附近局和距离 -> 同城筛选；复杂城市玩法属于二期/三期。

**当前实现**：基础地图、定位、附近局、距离、城市码和地图入口已存在；复杂地图页面通过子包保留但未作为一期入口。

**不符合项**：

- `miniprogram-client/api/modules/map.js` 已将 `map/my-city`、`map/play-pages`、`map/checkins`、`map/blind-routes`、`map/challenges` 等二期方法改为显式 disabled，不会再误请求后端；后续只需修正静态检查脚本对 disabled 方法的识别。
- 真实地图 Key、域名和真机定位精度未验收。
- 地图半径后台配置与环境配置存在两套来源，需统一优先级。

**等级**：P1 / 二期边界问题。

### F19 PC 后台、RBAC 和操作日志

**要求流程**：管理员登录 -> 角色权限 -> 菜单和接口鉴权 -> 审核/运营/财务/数据分级 -> before/after 日志 -> 导出。

**当前实现**：后台登录、权限码、角色、操作日志、快照字段和多个业务模块均有实现。

**不符合项**：

- 真实权限矩阵和浏览器 E2E 未完成，不能只以默认角色 seed 判定通过。
- OpenAPI 与新增后台路由的静态差集已为 0；仍需通过浏览器 E2E 验证菜单、按钮和接口权限一致。
- 固定格式导出、导出下载权限、敏感字段展示权限和操作日志完整查看权限需逐角色验收。

**等级**：P1。

### F20 数据看板、行为、导出和 AI 数据基础

**要求流程**：用户行为/局/评价/位置/信用入库 -> 后台看板、漏斗、留存、导出 -> AI 二期读取脱敏数据。

**当前实现**：行为、漏斗、留存、导出任务、AI 数据快照和 IM 导出开关均存在。

**不符合项**：

- 固定格式导出和对象存储下载未完成完整验证。
- 漏斗、留存、用户数、局数、评价数的统计口径缺少统一验收基线。
- IM 导出虽有权限开关，但敏感字段脱敏、导出审计和长期留存策略仍需核验。

**等级**：P1。

### F21 部署、数据库迁移和生产配置

**要求流程**：空库迁移 -> seed -> Go API/资金服务/Redis/对象存储/IM 启动 -> 健康检查 -> 备份/回滚 -> 真机验收。

**当前实现**：Docker、迁移、seed、Nginx、Go API、Java 资金占位服务和健康检查文件均存在。

**不符合项**：

- Go API 房间确保接口签名问题已修复，全仓编译已通过。
- 生产 API 和 IM 域名已部署；当前只剩腾讯云短信真实 Key/审核状态需要完成，其他生产服务按已部署状态继续回归。
- 空库迁移、重复迁移、备份恢复和跨服务启动顺序缺少本轮验收记录。

**等级**：P1 / 外部短信前置条件。

### F22 OpenAPI、前端路由和自动检查

**要求流程**：前端 API -> Go 路由 -> OpenAPI -> 测试用例三方一致；新增接口必须同步。

**当前结果**：

- OpenAPI 静态检查已通过，当前 Go 静态路由缺失为 0。
- 地图二期方法已改为显式 disabled；静态工具仍会把保留的方法名报告为缺失，需要在脚本中识别 disabled 接口。
- 页面流脚本已解析 `subPackages`，当前 12 条一期功能流检查全部通过。

**等级**：P1；脚本问题已修复，后续仅需随新增页面持续维护。

### F23 前端业务兜底与 Mock 数据

**要求流程**：真实接口成功 -> 展示真实数据；接口失败 -> 空态/错误态；不能展示假用户、假订单、假金额或假局。

**当前实现**：大量业务默认值已迁移到后端配置或 mock seed，但仍保留多处 `DEFAULT_*` 和 `FALLBACK_*`。

**不符合项**：

- `game/share`、`success-guide`、`success-expert`、`role/flow`、`map/index` 等页面仍有可能在接口失败时显示默认业务内容。
- `api/mock.js` 保留大量示例用户、订单、局和文案；需要明确只能在本地开发模式启用，不能进入体验版/正式版。
- 小程序 Mock 与 Go API 的字段和默认值没有自动契约校验。

**等级**：P1。

### F24 一期、二期、三期边界

**要求流程**：一期只交付邀请、实名、角色、组局、审核、入局、IM、确认、评价、成长、基础分润、举报和后台；AI/复杂地图为二期，元宇宙为三期。

**当前结论**：边界总体已在文档中明确。

**不符合项**：

- 部分前端路由和 API 仍保留复杂地图、城市玩法和推荐占位，容易被误判为一期已完成。
- 真实支付/退款/分账属于二期，但当前收益和资金占位接口需要在验收材料中明确标注“占位”，不能写成正式支付完成。
- 原始文档中 IM 文件是否一期必须项与后续甲方要求存在冲突；按最新要求以文字、图片、语音、文件为准，私聊语音仍保持关闭。

**等级**：P1 / 口径管理。
